基线为 `84ec8c74e0c23390b9bde975a16f92568a744619`，规格采用 v1.14 已编辑板与后续确认。纳入本地投掷、巴投、钩绳、翻转模糊、终结与助战演出。保持93张当前卡、20／35／25普通奖励池和初始卡组。

## 最终行为

- 燃血、残心、发掘、守势及其余数值、费用、升级、杀气伤害来源和打击·打击回手规则见 `card-catalog.md`。三张退役卡、独占 Power 和自定义遗物标题字体移入本地 `.local-reference/v0.2.17/`，不编译、不打包。共享卡图继续保留给当前模型，Kreon 数字字体保留。
- 无星之夜每发手里剑仍正常造成伤害。每次原生批量弃牌最多生成一张强·手里剑，每位玩家单独计数；独立弃牌和嵌套预见各有自己的批次。批次状态仅属于原生异步命令，不加入全局回合调度。按用户要求，这项上限不追加到中英文卡面或 Power 说明。
- 预见先将全部选中牌移出可抽取范围，再执行原生批量弃牌及奇巧。掌打由一个原生随机多段攻击命令结算，活力覆盖完整攻击。从容和守势使用 Unpowered 格挡。
- 最后一名敌人被黑炎击杀时，该张黑炎仍完成本次自伤；宿主确认战斗结束后，其余黑炎停止。保留原生分裂、召唤和事件转阶段判定。
- 旁白为默认开启的本地设置，排队与实际播放前均检查，角色语音和音乐独立。
- 泽渡决斗及黑暗忍者均提供一件原生随机遗物与对应专属遗物，手动领取。普通助战领奖分支不增加这些奖励；失窃牌仍逐张领取或放弃。

## 音乐来源与修正

RitsuLib 0.6.2 的自定义 BGM 使用映射 FMOD 实例，原版 Godot Proxy 的 `_musicEv` 并不指向这个实例。此前读取它会丢失播放生命周期。生产代码改为原生音乐控制器与公开 FMOD event description；SmokeDriver 对 RitsuLib 私有实例的读取仅用于核对真实播放状态。

泽渡从实际阶段恢复音乐，选择阶段切换先于动作收尾等待；音乐延迟屏障优先于 RitsuLib 拦截，覆盖原生自定义音乐及参数调用。黑暗忍者删去旧代理捕获和整场轮询，只在死亡时观察实际 outro，离开事件即清理并恢复幕音乐。保留原有事件 ID 和存档格式。

FMOD 三个事件关闭等拍转场，使用0.12秒短过渡，保持原版音乐总线路由。源项目、可重放的 XML 差异和构建方法见 `NinjaSlayer/audio/fmod/README.md` 与 `tools/fmod/music-v0217.patch`。实际 bank 已重建，8,296,576字节，不发布 Master.bank。
