# NinjaSlayer 1.0.13

落实用户保存的 v1.19 编辑板剩余现役差异，并追加用户确认的应变重做。归档、备注、卡图及布局不重新解释为实施需求；93个卡牌模型、80张普通奖励、初始牌组及模型ID保持，无新存档字段或迁移。

| 卡牌 | 基础／升级规则 |
| --- | --- |
| 螺旋回转跳 | 伤害8／12；群攻后激发并清空手里剑一次，不再生成库存 |

## 蜂群卡死

玩家反馈包记录预览0.111.0、忍者杀手1.0.12。已用工坊下载的原始DLL（SHA256 `a33d3582c43363edbe214e882fc4e6678b983d022b0e689d86522085a2cc3015`）在原生伤害命令重现：小季触发 `PersonalHivePower.AfterDamageReceived`，原生只特判Osty，使用小季的空玩家创建状态牌，随后 `AddGeneratedCardsToCombat` 抛空引用。原日志中的回合循环终止与此一致，不能把第一回合预见当作已证实的原因。

新增精确必需Patch，在小季、森林泽渡、由佳乃或折纸飞弹的玩家方伤害满足蜂群触发条件时，创建状态牌前跳过蜂群反应。保持真实攻击者、伤害属性和正常回调；不把攻击者映射给主人、不吞异常、不提供全局免伤。本人和原版Osty仍触发蜂群；荆棘、反射和火焰屏障仍反击实际随从。其他模组宠物不改变。

## 验证边界

行为契约覆盖四类友军、两个主人模型、主人生命／奈落生命／能量／能力／牌堆不受蜂群牵连、后续出牌、本人及Osty惩罚、真实攻击者反击，以及五张卡的基础／升级、库存／集中、生成者隔离、满手、叠加、原生回弹与东尼生成组件。保留预见不选、嵌套奇巧与空堆重洗回归。

隔离实机 `Release113` 重建玩家的8张手牌、16张抽牌及空弃牌堆，注入反馈中富足生成的谋定+（不声称还原前序整局随机流），按关键牌序执行并让小季在第二回合居合，随后继续出牌、结束回合及通过原生出牌获胜。普通和快速模式均检查。正式0.107.1没有富足，测试只替代其注入结果之前的占位槽，不增加运行时兼容逻辑。

本机只有预览完整安装。尝试以经MVID核验的0.107.1原始程序集配合现有0.111.0原生引擎及资源包重建正式隔离输入，启动出现Sentry资源不匹配，RitsuLib按0.111.0版本信息选错变体，随后的实现程序集归属检查失败。该尝试是失败证据，不是正式实机通过，没有降低或绕过检查。

用户于2026-10-05明确确认“只真实验证一个就行”，本次据此以完整预览0.111.0客户端的隔离实机通过作为发布门槛，保留正式0.107.1／预览0.111.0的DLL行为及Patch事务契约。正式完整客户端实机、macOS/Linux及独立多人客户端未运行，不作已验证声明。发布脚本新增可选 `ValidationChannel`（默认stable，保持旧调用兼容），本次显式选择preview导出运行目录；始终显式更新既有条目3776911445，并用真实客户端数据目录运行Steam元数据工具。
