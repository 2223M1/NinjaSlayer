## 沢渡 SL 慢的归因与计时

玩家日志 `godot2026-09-28T19.11.30.log` 未明确标记问题发生的那次 SL，单靠该日志不能断言耗时来源。用户推测为助战阶段；本次据此在本机原生 Continue 进行对照，不变更决斗 SL 回到助战阶段的现有语义。

旧版 `EventRoom.EnterInternal → AfterEventStarted → 入场 Tween` 等待入场结束，但模组 Transition 在房间加载结束前冻结 NRun。两者相互等待，实机记录出现 `NinjaSlayer transition exceeded 30 seconds; forcing input and screen release.`。旧测量 36,170 ms 含测试脚本的 240 帧等待，不是净加载时间。

修复把模型初始化和音乐请求留在原生加载顺序，仅通过既有 Transition barrier 延后入场演出与随后开战；加载钩子不等待冻结中的 Tween。不新增超时、轮询、后台保存或加载管理器。曾延后整个事件初始化，导致重载 BGM 被随后原生音乐更新覆盖；该方案已撤回。

去掉人工等待后的同次进程实测（preview 0.111.0、RitsuLib 0.6.2、正常速度）：

| 场景 | Continue 到过场结束并显示战斗 | 之后到首轮可出牌 |
| --- | ---: | ---: |
| 普通战斗 | 2,415 ms | 3,393 ms |
| 沢渡助战 | 2,523 ms | 5,112 ms |
| 黑暗忍者事件 | 2,724 ms | 0 ms（显示原生事件选项） |

沢渡的后半段约为入场 750 ms、原生开战流程 3,403 ms、竹击 948 ms；这是已显示战斗中的首轮演出，不能称为黑屏加载。验收以“Transition 结束进入战斗”为准，不能把首轮攻击或人工等待混入加载数字，也不取消原生抽牌及伤害同步来缩短指标。

`build/034/after-load-03` 的原生实机流程整体通过：普通房间与事件 Continue、事件 BGM 恢复、提前移动且重排不拉回、怪物死后可用卡牌输入、结束回合选择、决斗即时切段、问候、胜利 outro 停止、黑暗忍者 SL 与 outro、下一房间恢复原版音乐、设置页可打开。无截图／录屏。测试探针只记录阶段时点，不改变等待和结算。

## 验证边界

既有处决、单箭与奈落图标的修复前后证据见 [先前验证](combat-regression-20260928.md)。用户未亲自证实游戏单次射箭重复扣血，旧剧场脚本安排了两次行动；不能宣称修复了已证实的重复扣血故障。

产品契约包含基础／升级规格、生成牌减费隔离与重复结算及满手溢出、备战在能力前发射、全格挡／无目标／无库存／强手里剑排除及持有者隔离。双宿主构建／契约与网络测试的最终结果追加在本记录，构建不等于实机通过。

未执行的实机范围：stable 完整游戏、四人联机、全部完整／简短／人工制品／跳过／暂停组合、所有音频逐条人工听验、两幕所有击杀来源与重载排列组合。没有使用 ninja5080。
