# 官网统计分页内存修复

1.0.22 的工坊包已发布并下载回验；官网在提交 `d0f2f6f95edd9c0d0ce1ce7ffd9947929a71a5c0` 的 [Pages 构建](https://github.com/2223M1/NinjaSlayer/actions/runs/38119534665) 中耗尽约 4 GB JavaScript 堆，退出码 134。

`dashboard/posthog.mjs` 原先保留全部原始查询结果，最多 50 页、5 万条，再交给 `normalizeEvents`。移除这个原始结果累积列表，将原有按局去重、冲突集合和计数器归入 `data.mjs` 的 `RunHistorySamples`，逐页处理并释放原始响应；只保留统计需要的有效局记录。生产调用者为 `build-pages.mjs` 和本地管理页面的 `server.mjs`，均直接接收整理后的数据。本地文件导入继续使用 `normalizeEvents` 的原有输入及返回结构。

查询时间上界、时间戳/UUID 游标、1000 条分页、5 万条上限及截断标记不变。保留 UInt64 玩家 ID、跨页去重、较高读档次数替换、相同读档次数的胜负冲突与联机贡献合并规则。不丢弃历史统计，不提高生产进程堆限制、不添加强制 GC、缓存、吞异常或新回退。

验证：仓库检查和 81 项网站测试完成，80 通过，1 项因未提供独立宿主 fixture 按既有条件跳过。新增跨页冲突/读档替换/ID 回归，以及 128 MB 堆下的 5 万条合成无效大记录测试。相同输入下，旧实现因堆耗尽退出 134；新实现完成全部 50 页，拒绝数为 50000，截断标记保留，峰值进程 RSS 282256 KB（RSS 包含堆外内存，不等于堆限制）。这是有界合成输入的回归证据，生产 Pages 回验另行记录。

本次只改网站统计读取和对应测试，不改 C#、Patch、宿主兼容分支、存档迁移或已发布工坊包；新增状态只归属一次遥测读取，文件导入和远程读取复用同一整理规则。
