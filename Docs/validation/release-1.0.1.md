# 1.0.1 预见牌堆计数与公开发布配置

实现基线为 `4459413f4c38668f8c62aa11771512161cfdbd1c`；已发布 1.0.0 产品源码为
`15c41dad318baaba6b50d955bdc4fb8787e88a0f`。本轮不改变卡牌数值、模型 ID、93 张卡、奖励池或存档结构，
因此不调整独立卡牌规格和卡牌目录，继续支持 0.3.8 及之后跑局。

## 问题与修复

预见为避免弃牌回调抽到本次已选中的其他牌，先把整批选牌移至原生 Play 牌堆，再批量弃牌。
此前 `CardPileCmd.Add(..., skipVisuals: true)` 同时静默移除来源牌堆，遗漏原生 UI 通知。
两宿主 `CardPile.RemoveInternal` 的非静默分支会发出 CardRemoved、ContentsChanged、CardRemoveFinished；
`NCombatCardPile.Initialize` 订阅完成通知维护显示计数。

移除该 skipVisuals 参数，让原生移牌命令负责动画及计数通知；整批移出仍在弃牌回调前完成。
没有添加计数补丁、轮询、手动改标签或全局同步器。实际牌堆内容、奇巧、手里剑和嵌套预见的机制保持。

原生依据为本机 `Slay the Spire 2 v0.107.1` 与 `v0.111.0/src/Core/` 中
`Commands/CardPileCmd.cs`、`Entities/Cards/CardPile.cs` 及 `Nodes/Combat/NCombatCardPile.cs`。
两版均把 skipVisuals 传给静默移除参数；本修复不需要宿主条件分支。

## 复现与检查设计

- 已发布 1.0.0、preview 0.111.0、RitsuLib 0.6.3，本机隔离后台桌面：鼠标确认弃三张后，实际剩 5 张，显示 8 张。
  修复前检查点见 `release-1.0.1-scry-baseline.json`。
- 实机夹具先通过手牌移入抽牌堆，并断言预见前显示等于实际。直接创建牌放入 Draw 的旧夹具没有播放入堆动画，
  会掩盖缺少移除通知的问题；那次结果不能用作修复前复现。
- 产品契约新增零选、单选、批量弃牌和消耗路径的三种原生通知次数检查，以及嵌套预见的移除通知检查。
  原有弃牌触发抽牌隔离、奇巧、持有者和网络选择契约继续执行。
- 实机入口扩充普通／快速／瞬间模式的抽牌堆实际值与显示值比对，以及零选、单选、弃空和消耗后
  抽牌堆／弃牌堆／消耗堆三个显示值的比对。继续回归确认按钮与消耗堆不重叠、主动查看牌堆及假商人尺寸。
- 现有居合动画契约在本轮两次用墙钟测得约 0.481 秒，因距一帧下界约 2 毫秒而失败。
  该断言现改为累计 Godot ProcessFrame 的 delta，使用与 Tween 相同的时钟；原来的 0.5／0.25 秒目标、
  帧容差及命中位置断言保持，墙钟只作失败诊断。未改动画产品代码。
