# 1.0.2 首通反馈、作者回应与 MinionLib 兼容

基线为已发布 1.0.1（主分支 `2db3280`，产品 `1de86cf`），纳入本地 `8fe5eab` 的反向处决归位修复。
卡牌、模型 ID、奖励池和跑局存档结构没有变化，故不调整卡牌规格；继续支持 0.3.8 及之后跑局。

## 实现边界

- `FirstVictoryFeedback` 使用 RitsuLib `RunEndedEvent`，原生标准模式、当前本机角色为忍者杀手、原生角色胜场刚成为 1 才安排邀请。已有胜场的档案不补弹。通过结算页 `AnimateIn` 的完成时点打开既有 F2 表单，按档案保存“已展示”。与手动 F2 共用进行中的打开任务；新局、读档、主菜单及档案变化使待执行邀请失效。展示不等于发送，不修改统计授权。
- 反馈处理记录使用 `feedback-review/<UUID>` 独立 KV 对象，默认未解决；只包含状态、最多 5000 字符的纯文本回应和更新时间。写前验证原来信完成标记、元数据散列及已有记录，拒绝损坏读取或过期反馈。原正文、附件、校验值不变；回应使用原反馈接收时间加 180 天的到期时间，随管理／容量删除清理。
- 本机后台保留来源和 Host 校验，增加筛选、未保存提示、保存与清空、手动同步回执。公开页面只投影已同意公开的来信及处理信息，使用 textContent；截图、日志和凭据不进入 Pages。手动同步必须取得完整最新反馈，否则终止部署；计划任务失败保留上一份完整快照。
- MinionLib 仍为可选。只认可官方守护者临时扣血抑制补丁的 Harmony owner、程序集名、完整类型名、静态 bool 返回及参数名称／类型。未知扣血改写仍被检查。奈落吸收在 MinionLib／Loadout 判定后进行；已实际吸收的记录仍关联最终 DamageResult，保持海克斯语义。
- 反向处决提前预判先询问原生 `Hook.ModifyUnblockedDamageTarget`；重定向时由后续真实扣血决定，不提前锁定玩家死亡。没有替伤时，预判计入奈落生命。保留命中同步；不接管守护者溢出分配。
- `8fe5eab` 的归位修复避免在原生死亡结算已经重挂角色显示节点后，继续写入旧父节点坐标。身体演出与原生死亡界面布局均保留。

## 证据与版本边界

行为依据是两个精确宿主版本的 `RunManager.OnEnded`、`ProgressSaveManager.UpdateProgressWithRunData`、`NGameOverScreen.AnimateIn`、`NFeedbackScreenOpener.OpenFeedbackScreen` 与伤害重定向接口。胜场在生命周期回调之前更新；每日／自定义不会增加标准胜场。stable 的 `RunManager.WinRun` 为私有，测试通过精确反射调用；产品不反射此方法。

守护者契约直接加载官方 DLL 并安装真实 Harmony 补丁，测试临时玩家扣血完全抑制、两只守护者完全挡伤与溢出、奈落部分／完全消耗、最终致死及无守护者原有行为。分别在奈落补丁之前和之后安装官方抑制补丁，核对两种顺序。新增预判断言要求替伤和奈落生命不得提前预留反向处决。

最终运行包来自 PR #154 的干净合并提交 `36cfde86520291e133935d575dd4e03ef53ee788`，主分支 CI 通过。stable 产品 DLL SHA-256 为 `decc413bf6c1db76bddba404054da380834c66b63c674118698859429304c8e7`，preview 为 `9533427954d2f9a09b0d1a54e9e38dbc164ada8c465bc4a2c95a857f44f8e40d`。实机使用 RitsuLib 0.6.4；编译兼容包版本仍为 0.5.12。完整文件散列、宿主 MVID 和各次实测见相邻 JSON 证据。

最终重测曾遇到夹具问题：随机首战选中 ShrinkerBeetle 的减益首轮，旁观 Nibbit 也只增益，因没有任何攻击而触发“未杀死一血玩家”的超时。SmokeDriver 现改用原版 Nibbit 固定单段攻击及增益旁观者，并调用原生敌方布局，防止无槽位的新增怪物互相重叠影响像素检查。双宿主重新执行普通多段处决、保存重载和反向处决，保留所有原有像素、坐标、UI 与结算次数断言，均通过。测试驱动源码为 `532f47394429899b0705cdb53d284b83dece28a3`；游戏产品未因夹具修改而重建或更改。失败记录不算通过。

Loadout 0.5.8 与海克斯 0.9.7 的实际扣血前缀在双宿主契约中通过，包括奈落吸收记录、濒死保命与真实致死。海克斯使用对应宿主的运行 DLL，未将其通用加载器误作测试程序集。官方 MinionLib 在奈落补丁之前／之后安装的四组契约均通过。

已执行的检查包括 375 项逻辑测试、Worker／网站 68 项（67 通过、1 项原生遥测外部夹具未提供而跳过）、仓库一致性、兼容清单、构建边界、双宿主产品与 SmokeDriver、完整 DLL 契约。首通实机夹具使用原生胜利与结算入口，未实际游玩整局；确认新档案首次、关闭不发送、重复胜利回调、再次通关、老档案，以及自定义模式和其他角色排除。

浏览器后台验证使用隔离合成来信，检查保存／清空回应、状态独立、重新打开和同步失败提示；不向真实玩家来信写测试回应。HTTP 测试覆盖来源拒绝、默认记录、私有附件投影、过期／损坏读取、快照失败保留及真实空反馈替换。

兼容 Worker 已先部署，版本 ID 为 `b66efe39-f0b8-4b6e-8681-b4cc01efe34e`。真实本机后台的“立即同步官网”已触发并完成 [Pages 36942407863](https://github.com/2223M1/NinjaSlayer/actions/runs/36942407863)。公开页面中英日状态筛选、详情和作者回应区域通过浏览器检查；现有四条同意公开的来信默认未解决，私有附件不进入快照。
