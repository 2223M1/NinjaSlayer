# 1.0.3 编辑板调整、死亡与复活

基线为已发布 1.0.2，源码主分支 `2e1ed564c76908049d72f0d3c4840ee89de2d3a2`。仅提取 v1.18 已编辑文件的保存差异，本轮补充确认优先；93 张当前卡、20/35/25 奖励池、初始卡组及模型 ID 不变。

## 卡牌

- 钩绳固定降低 4→6 力量并给予 1→2 虚弱，不再依赖空手道。
- Chop 伤害 4→7；Chop Strike 伤害 11→13；Spiral Jump 群伤 7→11、手里剑固定 2；备镖格挡 8→10、手里剑 1→2。
- 左上勾拳伤害 10→12；嘶哈治疗 6→9；强攻伤害 16→20；手里剑生成固定 1 费；乘胜每次符合条件的发射获得本回合力量 2→3。
- 半月圆规踢为 0 费群攻，伤害 10→13。手里没有茶道不能打出，有茶道时必须选择一张消耗，再攻击一次、本回合翻倍该实体自身伤害并回手。原生消耗和临时复制牌移除优先；复制后的临时增量各自清理。
- 龙卷拳群伤 4→6，按原生天际钻头处理 X；结算后的 X 至少 4 时攻击次数翻倍。整次原生多段命令共享活力，并在攻击结束后消耗；删除旧逐段脆弱。
- 奈落之力为 1 费攻击，伤害 8→10、脆弱 2→3，生成黑炎，删除原空手道收益。
- 同步三语动态文案、独立规格、目录及可选东尼组件。编辑板采用基础／升级合并文案，不拆成两套说明。

## 死亡与复活

只有敌对怪物的实际攻击伤害进入击飞／反向处决。无来源伤害、自己造成的伤害、敌人施加的非攻击伤害均走自杀倒地。嵌套伤害捕获明确记录伤害属性，避免继承外层怪物攻击上下文。

已在安装的 1.0.2 原版游戏进程中复现：两个原生玩家模型，忍者杀手被萎靡杀死后，队友击败敌人，`ReviveBeforeCombatEnd` 调用复活动画时因奈落外观节点找不到而抛异常，`CombatWon` 始终没有触发。死亡旋转临时重设父节点后 Godot 清除了场景 owner；恢复只搜索 owned 节点漏掉了该节点，并且阴影刷新早于身体和外观恢复。

修复使用当前角色树内的实际节点（包含运行时临时父节点），先恢复身体与奈落外观的同级关系，再刷新瞄准姿态／阴影并删除死亡枢轴。动画等待沿用现有具备退出／取消处理的 TweenPlayback。

自杀倒地后复活直接站起；击飞后复活调用进入新一幕使用的 `AncientEntranceAnimation` 六种随机入场，沿用原概率。复活入口仅使用视觉随机数，不推进跑局随机流。保持原生本地 UI 恢复和命中框逻辑。

## 验证口径

工作候选已通过 375 项逻辑测试、仓库一致性、兼容清单、构建边界、stable 0.107.1／preview 0.111.0 产品与 SmokeDriver 构建，以及两宿主完整 DLL 契约。新增卡牌契约覆盖 X=0/1/3/4/5、升级、群体活力、茶道选择、实体复制、临时伤害清理、消耗优先、奈落之力与钩绳。

两宿主隔离后台桌面的渲染夹具已通过萎靡、敌人非攻击伤害和敌人攻击三种致死来源；要求真正收到原生 `CombatWon`，并检查复活生命、入场调用次数、身体／外观归位和死亡枢轴清除。龙卷拳实测 X=4、7 活力，八段对每名敌人合计 88 伤害。实际 RitsuLib 为 0.6.4，编译兼容包为 0.5.12。

最终发布的源码 SHA、DLL 散列、宿主 MVID 和最终运行结果写入相邻精简证据。工作候选的结果不代替最终源码验证。

双宿主两端原生 ENet 契约通过；preview 额外验证两名玩家各自选择并消耗恰好一张茶道、伤害翻倍和回手的一致性。可选东尼程序集通过真实组件执行、临时伤害复制／回合清理／降级、X 多段、升级和存档重载契约；其 0.3.102 仅支持 preview，不声明 stable 支持。
