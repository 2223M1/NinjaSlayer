## 原版临时生命依据

本轮直接核对已安装 **StSLib 2.12.0** 的 `StSLib.jar`。素材来源及 MIT 许可仍见 `ASSET_MANIFEST.md` 和图标旁的许可文件，未修改原始 PNG；其 SHA256 为 `0555b89f458e8ff74c3877d1e78c97c8a583b61fac822ffa1a82eeff1c0f7dbc`。

原版 `RenderHealthBar` 使用 `x + BLOCK_ICON_X - 16 + hb.width` 绘制 64 像素爱心；`AbstractCreature.BLOCK_ICON_X = -14 * scale`，换算中心为血条右端 +2。当前布局据此改为左右偏移 -30/+34、上下偏移 -36/+28。此前把图标放在血条外的实现不符合这一位置。

紫色直接取自 `NinjaSlayer/scenes/vfx/burn/ninja_slayer_additive_step_fire.tscn` 的外焰 `OuterColor = Color(1, 0.192157, 1, 1)`，火星及地面火焰粒子也使用该颜色。只调制爱心图标，白色标签不继承紫色；没有新增颜色管理层。

原版 `PlayerDamage` 的插入点紧接 `decrementBlock`，先扣临时生命，再处理缓冲、钨合金棍等生命损失效果。对应的当前行为为：

- 伤害先经过无实体等伤害修正和格挡，再消耗奈落生命，溢出部分进入生命损失钩子。
- 完全吸收不算真实掉血，不消耗缓冲，不触发百年积木、妖刀碎片和暗忍的掉血偷牌，也不破坏杀气·直气的无伤资格。
- 伤害命令产生的不可格挡自伤同样能被吸收。直接设置 HP、强制死亡不通过这个伤害入口。
- 可叠加超过生命上限，跨回合保留，不属于治疗，也不增加真实生命上限；战斗结束由原生 `Player.AfterCombatEnd` 清空。

实现只替换精确 `CreatureCmd.Damage(IEnumerable<Creature>, …)` 异步状态机内的三处 `Hook.ModifyHpLost` 调用，在 `BeforeOsty` 阶段吸收后继续原生钩子。只读伤害查询不会扣除奈落生命。stable 与 preview 的 `CardPlay` 参数差异保持在此特性的编译分支内。未建立 STS1 第三方临时生命扩展接口的跨游戏兼容层。
