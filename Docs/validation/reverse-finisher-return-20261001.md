# 反向处决攻击者在结算界面消失

本地修复基于 `2db3280b7b5d15d17da3e992d41df393f99d79dd`，不升级版本、不上传 Workshop、
不安装到日常游戏。原混合工作树未改动。卡牌机制、模型 ID、存档及卡牌目录不变。

## 原因与修复

stable 0.107.1 和 preview 0.111.0 的
`Core/Nodes/Screens/GameOverScreen/NGameOverScreen.cs` 中，
`MoveCreaturesToDifferentLayerAndDisableUi` 会把真实 `NCreature.Visuals` 移交给结算界面，
保留全局变换，并正常隐藏血条及意图。

反向处决的清理发生在原生死亡回调之后。旧代码仍将击杀者的 Visuals 写回战斗局部坐标 `(0, 0)`，
覆盖新父节点中的位置；未参与处决的怪物没有这次错误写入。

现在处决归位插值、最终定位以及 FinisherApproach 的动画通道和释放，只在 Visuals 仍属于
原 NCreature 子树时写位置。原版接管后只释放处决资源，不覆盖结算界面布局。
没有怪物名单、结算界面补丁、重新显示血条或补造身体。

## 验证

- 已发布 1.0.1 本机 preview 复现：正常结束回合，由原版 Nibbit 执行真实攻击杀死 1 HP 玩家。
  另加一只 Nibbit 作为未参与攻击的对照。击杀者身体从全局 `(1424, 723)` 被错写为 `(-16, -17)`，
  Visible 仍为 true，原生新父节点已是 GameOverScreen。修复前最终回归断言失败。
- 候选 stable / preview 同一流程检查击杀者与对照怪物的实际渲染、原生移交后的全局位置、
  角色根节点不动、玩家死亡只提交一次、黑幕及输入锁释放。颜色采样仅在测试内存中进行，不保存截图。
- 产品契约新增身体移交到另一父节点后的归位、动画通道写入及释放检查，保留普通归位、武器接触、
  双朝向和 UI 根节点稳定的既有检查。双宿主完整契约及产品／SmokeDriver 构建通过。
- 375 项逻辑测试通过；仓库校验、兼容清单同步和差异空白检查通过。
- 实际 RitsuLib 0.6.3，编译包 0.5.12；宿主 MVID、候选 DLL 哈希及检查点见同名 evidence JSON。
  DLL 元数据使用基线 SHA，候选包含本轮工作树修复；不把它描述成从干净发布提交构建的包。
- 未执行：四客户端渲染联机、macOS/Linux，以及所有怪物逐个实机遍历。没有重新发布工坊。

排查时仅检查 Visible 或直接调用攻击命令会漏掉原生结束回合到 GameOverScreen 的交接，
因此正式回归使用真实结束回合和全局坐标断言。早期试探性运行不计为最终通过证据。
